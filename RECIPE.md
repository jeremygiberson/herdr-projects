# Projects

A project picker for the Herdr app. You keep a list of local git checkouts, each with its own settings: whether selecting it opens the checkout or a fresh worktree, how the branch is named, what git does first, and what starts in the new space. `ctrl-alt-p` (`cmd-alt-p` on macOS) opens a fuzzy-searchable list; Enter does what that project is set up to do.

![Projects](preview.png)

## What you see

A popup, 680px wide, top-aligned 40px down, up to 80% of the window high, on the theme's `popover` background.

- Title "Projects" with "Esc" on the right (other screens say "alt+b back · Esc closes").
- A 36px search box with an `accent` border.
- One 48px row per project (a scrolling list with a scrollbar; the wheel and the arrow keys scroll): a marker (`●` in the agent-status color when the project's folder already has a space, `★` when pinned, else `·`), the name, the folder shortened with `~`, the group at the right, then `checkout`, `worktree?` or `worktree` for the project's mode.
- A toolbar under the search box (`renderToolbar`): Add project, then Duplicate, Worktrees (not for a template), Edit and Delete (only when a project is listed), "acts on <name>" for the highlighted project, and at the right Import / export… and Show/Hide details. It wraps if the popup is narrow. The footer is only the line of key hints (and, without the card, the layout choice); the detail card has no action buttons of its own except Create worktree / Checkout (Use template for the template).
- The toolbar's **Launcher** button: "Launcher: add to layout" on a layout without the launcher blocks, else "Launcher: sidebar / status bar / tab bar / off". In the chosen block a **Projects** button (folder icon plus "Projects" in the sidebar footer and the status bar, the icon alone in the tab bar) opens the picker with `mod.open`. The same block runs the auto-layout watcher, which has no screen of its own; the button is all you see of it. A toast appears when the watcher sets a space up or cannot read the data file.

The **launch screen** (`renderLaunch`) replaces the old branch-name step. Enter on a project opens it, Shift+Enter opens it on the checkout, and a project with `quickLaunch` on skips it (unless its mode is `ask`, which needs a branch name). Rows, top to bottom, titled "Open · <name>" with "alt+b back · Esc closes" (⌘⌥B on a Mac):

- **Open as**: Worktree and Checkout buttons, defaulted from `worktree.mode` (`never` starts on Checkout).
- **Branch** (worktree only): a one-line box with the live `branch: …` preview and the note "from <remote>/<base> after a fetch · Enter launches". A typed name containing `/` is used verbatim as the branch (`feat/x` creates `feat/x`); anything else goes through the branch template.
- **Prompt**: a multi-line box prefilled from the first agent pane's `prompt`; empty starts the agent bare. Hint: "Enter: newline · ctrl+⏎ launches".
- **Agent**: a button "Agent: after setup" / "Agent: with setup" with the key hint ctrl+alt+T (⌘⌥T on a Mac). Only shown when this launch has setup commands (`startup.setup`, plus `worktree.setup` when opening a worktree); with none the timing is always "with".
- The footer's layout choice (ctrl+alt+L / ⌘⌥L) and a **Launch** button.

Keys: plain Enter in the prompt box inserts a newline; **ctrl+Enter** launches from anywhere on the screen; Enter in the branch box also launches. Cmd+Enter and Shift+Enter do the same as Enter in the prompt box (a newline), so on this screen Checkout is the Open as button, not Shift+Enter.

Ordering with an empty search: projects with an open space, pinned ones, recently used, then by name. With a query: best fuzzy match first (subsequence match on name, group and folder name; consecutive and word-start letters score higher).

The editor replaces the list in the same popup, in four sections chosen by buttons under the title. **Project:** Name, Folder (+ Browse…), Group, Pin to top. **Worktree:** the mode button (ask / always / never), Branch name, Worktree folder, Space name, an "Open the repo's space first" toggle, and two multi-line boxes: **Copy from the checkout** (one path or glob per line, relative to the checkout, copied to the same relative path in the worktree) and **One-time worktree setup** (one command per line, run once when the worktree is new). **Git:** Fetch first, Fast-forward checkout, Remote, Base branch. **Startup:** Every-open setup (a multi-line box, one command per line, run on every open), an Agent timing button (after / with setup), a "Quick launch" toggle and a "Run setup inline" toggle, then a **Tabs** list (one 28px row each: name, folder, `N panes` or the command or `plain shell`) with Add tab, Remove tab, Move up, Move down; the selected tab's Name and Folder boxes, and its Command box when it has no panes; a **Panes** list (type, command or agent, direction) with Add pane, Remove pane, Move up, Move down and a "Panes from:" button per shipped or user layout that replaces the tab's panes; the selected pane's type buttons (agent, shell, command), Direction button (not on the first pane), Folder box, Command box (command panes) and, for an agent pane, an Agent button per installed agent from `knownAgents()` plus Shell, Agent command, Agent arguments, First prompt and a Prompt delivery button. Buttons: Delete (asks for a second click), Cancel, Save. Tab moves between the fields of the current section.

## How it behaves

- A single click highlights a row; a double-click (two clicks on the same row within 450 ms) or **Enter** opens the launch screen (above) on that project; **Shift+Enter** opens it on the checkout. A `quickLaunch` project skips the screen and starts with its defaults. Launching follows the Open as choice:
  - Checkout: focus the project's space if one is open (a space in the project folder, else one below it, `spaceShows`: a first tab with a folder opens there), otherwise fetch (if on), fast-forward (if on and safe), then the setup below and a space on the checkout.
  - Worktree: create a worktree and open a space on it. The `{slug}` part is the typed name, else the time (HHMMSS).
- **The launch sequence** (`start`, `prepareLaunch`): check the layout, then for a worktree `git fetch`, `git worktree add --no-track -b`, then `isNewWorktree` (no `.projects-setup-done` in the folder). A new worktree gets `worktree.copy` (`copyInto`: globs relative to the checkout, existing destinations are skipped and never overwritten, missing sources are logged and skipped, one summary line on the busy screen). The setup list is then `worktree.setup` (only when the worktree is new) followed by `startup.setup` (every open, checkout or worktree). Variables in every command, as `{braces}` and as env: `{main}`, `{folder}`, `{branch}`, `{repo}`, `{name}`, `{home}` and `PROJECTS_MAIN`, `PROJECTS_FOLDER`, `PROJECTS_BRANCH`, … (`expandSetup` fills only those six braces, never one after a `$`, so `${PROJECTS_MAIN}`, `awk '{print}'` and `jq '{x: .y}'` stay as written; copy patterns use it too). `prepareSetup` in `setup.js` does the copy, builds the chain and adds the marker to git's exclude file. The steps are joined into one shell line, `cd <folder> && sh -ec "$(printf '%s\n' '<step1>' '<step2>' …)" && touch .projects-setup-done` (`setupScript`): the steps run as one `sh -e` script, one per line, so a `cd` reaches the steps after it, a `# comment`, `;`, `&` or `||` stays on its line, and the first failing step stops the script. The line is started through `inUserShell` (`sh -c 'exec "${SHELL:-sh}" -ilc "$1"' sh <line>`): the person's own shell, interactive and login, because a program the app starts gets only the login PATH, without what `.zshrc` or `.bashrc` adds (nvm's node, pnpm). Tab commands and command panes go through `inUserShell` too; a line typed into an existing shell does not need it. The `touch` is there only for a new worktree that has setup steps and inline setup off. `buildWorkspace` makes the space and tabs and starts that line in a terminal. The mod's own work is over in seconds; nothing waits for setup.
- **Branches, copy and setup lists** are one entry per line in the editor (and an array in the file). `;;` is not a separator anywhere: a command containing `;;` (a `case` statement) stays whole.
- **Agent after setup:** the agent pane's command is `<chain> && cd <the pane's own folder> && exec <agent command> [prompt] || exec "$SHELL"`: setup output scrolls by in the pane, the agent takes it over when the last step succeeds (the prompt goes in as an argument for `arg` mode), and a failing step leaves the pane at a shell with the output above it and no agent. For a `send` prompt a detached helper (`bin/send-prompt.sh`, started with `hc run --bg --rm --no-parent --no-notify`) types it when the agent is ready.
- **Agent with setup:** the agent starts at once with its prompt; the chain runs in its own tab, started as `hc run --bg --rm --no-parent --no-notify --cwd <folder> --label herdr.space=<id> --label herdr.tab=setup-<timestamp> -- sh -c '<chain> || exec "$SHELL"'` and renamed "setup" with `tab.rename` once it appears. The tab vanishes when setup succeeds and stays at a shell when it fails. When the new space can't be found or `hc run` fails, the busy screen says `setup did not start: …` instead of "setup runs in the setup tab".
- **The marker:** `.projects-setup-done` is written by the chain's last `touch`, so a worktree whose setup failed or is still running counts as new again next time. Its name is added to `info/exclude` in git's common dir, so it never shows in `git status` in the checkout or in any of its worktrees. Opening the same worktree again skips `copy` and `worktree.setup` and runs only `startup.setup` (and its marker is already there, so nothing new is touched). A worktree that existed before the mod counts as new on its first open.
- **Inline setup:** `startup.quickSetup` ("Run setup inline" in the editor) runs the steps as one script with `exec` (`inUserShell("<PROJECTS_* exports>; cd <folder> && <setupScript>")`, 30 s cap for the whole script) before the space is made, stops at the first failure, and keeps the popup busy meanwhile. The marker is written after the inline steps succeed too. No chain goes to a terminal.
- **Tabs and panes:** `startup.tabs` is the list of tabs the new space gets, in order. A tab has `name`, an optional `folder` (relative to the project folder or the worktree, absolute, `~` and `$VAR` expand) and either `command` or `panes`, not both; neither means a plain shell. A pane has `type` (`agent`, `shell` or `command`; inferred from an `agent` or `command` field), `command`, `direction` (`right` or `down`, default `down`), `from` (an earlier pane's name to split instead of the previous one) and `folder` (default the tab's; relative to the tab's folder). An agent is a pane type and may be anywhere; each agent pane carries its own `agent`, `args`, `prompt` and `promptMode`. The first agent pane (`firstAgent`) gets the typed prompt; later agent panes start bare. `workspace.js` (`buildWorkspace`) makes tab 1 with `space.new`, named through its `tab` field, the other tabs with `tab.new`, and each extra pane with `pane.split`; focus goes to the first agent pane, else the first pane.
- **Folder checks:** every tab and pane folder is resolved and checked before anything is created; a missing one stops the launch with `Tab "web" pane 1: folder does not exist: <path>` on the busy screen and no space is made. `tabPlan` refuses `Tab 2 needs a name`, a tab with both command and panes, a repeated pane name, an unknown type, a command pane with no command, a bad direction, and a `from` that does not come before the pane.
- **Old entries:** `normalize` turns a project-presets entry's agent, arguments, prompt and named layout into tab 1 (the layout's panes with the agent first) and each of its extra tabs (a string) into `{ name: <first word>, command }`; saving writes the new form, so a project-presets file copied to `projects.json` opens the same spaces.
- With alt, ctrl or cmd held (⌘ on macOS): **w** (or the Worktrees button) opens worktree cleanup, **d** (or Delete) removes the project from the list after a second press, **n** (or Add project) adds a project, **e** (or Edit) edits the highlighted one, **s** saves, **Tab** moves between fields, **alt+b** (**⌘⌥B** on a Mac: herdr owns ⌘B, so the Mac gets the cmd+alt chord like the layout and details keys) goes back one screen (not a bracket key: herdr binds alt-[ and alt-] to tabs and acts on them before the popup sees them); **Esc** closes the popup (herdr closes a popup on Esc itself and never gives the key to the mod, so the mod's own Esc branch only runs outside a popup; the debug log showed no `key escape` line).
- While working, the popup lists progress lines (`git fetch origin…`, `git worktree add …`, `copied 1 file`, `N setup commands run in the new space, not here` when the steps go to a terminal, `$ <setup command>` per step run inline, "setup runs in the setup tab" or `setup did not start: <why>`) and Esc does nothing; for a "typed after start" prompt with the agent starting at once it stays open, with a "Waiting for the agent…" line, until the prompt is sent, then closes. An error stays on screen until Esc.
- Worktree creation: `git fetch <remote>` (a failure is logged and the local ref is used), then `git worktree add --no-track -b <branch> <folder> <remote>/<base>`. A taken branch or folder gets `-2`, `-3`… up to `-20`.
- Fast-forward only happens on the checkout when it is on the base branch, clean, and can fast-forward.
- **Worktree cleanup** has a filter box (fuzzy, on branch and folder name) over a scrolling list of the repo's linked worktrees (`git worktree list --porcelain`, main checkout excluded) with the branch, folder, and badges: `open` (a space shows it), `uncommitted`, `locked`, `merged` (branch is an ancestor of `<remote>/<base>`) or `unmerged`. Enter or a click ticks the highlighted row; m (or Tick merged) ticks every merged, clean, unlocked one, and again unticks them; r (or the Remove button, labelled with the count) asks for confirmation and the second press removes the ticked ones with `git worktree remove` (never `--force`, so dirty ones are refused and reported). A merged branch is then deleted with `git branch -d`; an unmerged one is kept. The space showing a removed worktree is closed with `space.close`.
- **Space name and repo space** (worktree modes only): the new worktree's space is named from `worktree.spaceName` (variables `{name}` the project's display name, `{branch}`, `{slug}`, `{user}`, `{date}`, `{repo}`; an empty result falls back to `<name> · <branch>`). When `worktree.repoSpace` is on and no space shows the project's main checkout, a plain-shell space named after the project is opened on it first, then the worktree space, which herdr nests under it. If the repo's space is already open nothing extra is created.
- **Sections and the detail card:** without a search the list has headers (Open now: a space shows the folder; Pinned; Everything else), 30 px high among 48 px rows (`v_virtual_list` takes per-item sizes); headers are dropped while searching or when only one group is non-empty. Each row has an avatar tile in the space's color (`shared("space.colors")`, palette as in the `spaces` mod; an outline when no space is open), a status stripe that pulses (`loop("opacity")`) while the agent works, the matched letters in bold accent, and chips from `gitSummary` (branch, changed files from `status --porcelain`, linked worktrees), loaded three projects at a time after the list shows, unless `"gitInfo": false` is in the data file (it runs git in every project on every open). A 340 px card beside the list shows the highlighted project (agent: the first agent pane's agent, tabs: a `Tabs` row of tab names with `server ×2` for a split tab, branch, changes, worktrees, last opened from `projects.recent`, a mini drawing of each layout from `layoutRects`, what Enter does, and the Open/Checkout/Worktrees/Edit/Delete buttons). The card is ON by default (shared state `projects.detail`; ctrl+alt+I / ⌘⌥I or the Hide details button turn it off). On older herdr-core versions the popup burned a full core and a draw could be cut off ("This view could not be re-rendered … interrupted"); the herdr-core update fixed that, and with it the original card, layout pictures and buttons measured 2–3% CPU; the buttons then sit under the list and the layout choice is the footer's text chips. `mod.json` overlay width is 1060. A render builds as few elements as it can: hints are one row of bold keys and plain strings, card rows are a label and a string, background redraws are batched into one every 250 ms, and buttons have no hover callback (each cost tens of ms).
- **Pane layouts:** `projects.json` may hold a `layouts` list beside `projects` (kept when the editor saves). Two ship (`agent-terminal`, `agent-side-terminal`); a user layout of the same name replaces one. A layout is `panes`: the first is the agent, each next one has `direction` (`right`/`down`), a `type` (`shell`, `command` + `command`, `agent`), an optional `name`, and `from` (the pane to split; default the previous one). A layout may also hold `tabs` (a whole set of tabs that replaces the project's for that launch); one with `panes` replaces the panes of the tab holding the project's first agent pane (tab 1 when it has none). An agent pane left empty by a layout takes the project's first agent pane's settings, else becomes a shell. ctrl+alt+**L** (⌘⌥**L**) in the list or the launch screen steps none, then each layout for that launch (a selector under the list shows them all, the one in use lit; it bolds with an accent ring for a second after a change). Each extra pane is made with `herdr-app do pane.split {direction, pane, argv}` (its `pane` reply is the next pane's id); `argv` wraps the command so it starts in the project folder, since a split takes none. Focus returns to the first agent pane (`pane.focus`). Sizes are not set. An unknown layout name or a broken layout is shown before anything is created; a failed split is logged and ends that tab's panes, the space and the other tabs still open.
- **Import and export config:** alt/ctrl/cmd+X (or the Import / export… button) opens `mode = "backup"` (`renderBackup`): a file box (`this.backupPath`, default `~/Downloads/` + `exportFileName()` = `projects-config-YYYY-MM-DD-HHMMSS.json`, set afresh on each open) and Export / Import: merge / Import: replace. `exportData` writes `{ format: "projects-backup", version: 1, exportedAt, gitInfo, hideTemplate, layouts, projects }` with the home folder written as `~` in each project's `path` and `worktree.root` (`portablePath`); `parseBackup` also accepts a plain data file and rejects bad JSON, a missing `projects` list, another `format` and a newer `version`, each with its own message. Export to an existing file and Import: replace both need a second click (`this.backupConfirm`, cleared when the box changes); replace first writes the current file text to `<data file>.bak`, then `saveConfig(projects, raw, { layouts, gitInfo, hideTemplate })`. Merge uses `mergeProjects` (same name + folder counts as present; yours win; an incoming template is skipped when you have one) and `mergeLayouts` (by name). After an import `folderExists` flags projects whose folder is missing here. The demo file accepts `"view": "backup"` with `text`, `note`, `bad`.
- **Template and duplicate:** a project with `"template": true` is a template: no folder, never launched, always the last row under a "Template" header (tagged `template`, shown on its card with Use template / Edit / Delete). When the file has none and `"hideTemplate"` is not true, the picker shows an unsaved default template (`defaultTemplate()`: one agent tab with a shell split below it, ask mode) that becomes a real entry the first time it is saved. Enter (or Use template, or Shift+Enter) on a template opens the editor on `duplicateProject(template)`: name "New project", no folder, the template's settings; saving that needs a folder and runs the usual git-checkout check. Editing a template skips the folder check. **alt/ctrl/cmd+U** (or the Duplicate button) opens the editor on `duplicateProject(project)`: `<name> copy` (`uniqueName` adds 2, 3…), the same folder, not pinned. Add project starts from a *saved* template (`startFromTemplate`: its settings without name, folder or pin), never from the unsaved default. Deleting a template (either kind) writes `"hideTemplate": true` next to `projects` (kept by `saveConfig(projects, raw, extra)`); removing the key brings the default back. The template is skipped by git lookups, worktrees, launching and space matching.
- **Delete** (the button or **d**) shows "Remove \"<name>\" from the list?" in red; pressing d or clicking Delete again removes the project from `projects.json`, any other key cancels. The folder and its worktrees are left alone. The editor's Delete button has its own two-click confirmation.
- Selecting a project records it in shared state `projects.recent` for ordering.
- **Auto-layout watcher:** a launcher block (`projects-launch-sidebar`, `-status`, `-tabs`) loads this mod with `props().slot`; `init` then sets `role = "launcher"` and skips the picker (no search box, no reload, no snapshot timer), `render` draws only the button (`renderLauncher`), a block whose slot is not `shared("projects.launcher")` hides itself with `layout.hide`, and `init` drops `projects.recent` entries whose folder is gone. The same copy polls the spaces every 2 s (`watch.js`). A copy stays alive once shown, hidden or not, so each watcher acts only while its slot is the chosen one (`active`); "Launcher: off" makes no slot the chosen one, so nothing is set up. `cycleLauncher` rewrites a layout whose blocks still name the retired `projects-launcher` mod (`migrateLauncherBlocks`). The rules:
  - The trigger is a space appearing, never focus. Spaces present when the copy starts are already seen, and a space is considered once. A space that appears while the copy is inactive, or while this computer's layout is still loading (`machines()`: the app restoring its spaces at start), is only marked seen.
  - A space qualifies when it is local, has one tab with one pane, and that pane is a plain shell or an agent (`agents()` lists it, or the pane's `program.agent` is true: an agent at its trust prompt reports no status). Spaces the picker just opened (`projects.opening`) are skipped for 60 s.
  - Its folder is read once, at appearance. Matching: the repo (`repoKey`, the real path of the git common dir) against the non-template projects with `worktree.autoLayout`. Checkout or worktree comes from git dirs (`gitDir`, the folder's own git dir, against the common dir). A checkout (or a subfolder of one) is built in the project's folder; a worktree in the same subfolder of the worktree as the project has in its checkout. Only one project per repo may have auto-layout; saving one moves it from the other with a toast.
  - Else the global `autoLayouts` list, chosen by precedence repo+branch, repo, `*`+branch, `*`, built at the folder's top level; a repo that is a project with auto-layout off is left alone.
  - The build waits for the shared lock, then reads the space again: one that closed or no longer has one tab with one pane is left alone (logged, no toast).
  - A running agent is adopted as the project's first agent pane and setup (copy, the worktree and startup chain) runs beside it in a setup tab (timing forced to `with`). A plain shell gets a line typed into it once a shell is in front at a bare prompt: the chain then the agent for `after`, `cd <folder> && exec <agent>` (or the command) for `with` with the chain in a setup tab. Its tab is renamed to the plan's first tab name. Then the other panes and tabs; the new space's pane is focused only when it is the shown space. There is no prompt.
  - A checkout runs only `startup.setup`; a worktree without the marker also gets `copy` and `worktree.setup`. A `quickSetup` project's steps run through the same chain here, not inline.
  - The toast says `<project or layout> set up in <space>`, with `with N problems (see the log)` when the typed line, a split, a tab, the setup terminal or the prompt helper didn't happen. A data file that cannot be read toasts once, not every tick.

- `keys.json`: `"global": { "ctrl-alt-p": "mod.open:projects", "cmd-alt-p": "mod.open:projects" }` (ctrl-alt-p for Linux and Windows, cmd-alt-p for macOS; cmd-p is herdr's built-in space picker there, so it is not used), merged into the person's file. Ask before replacing a key they already use; `cmd-alt-p` is already the macOS default, so a clash there means choosing another key.

- Template variables: `{user}` (slug of `git config user.name`, else the local part of `user.email`, else `user`), `{date}` (YYYY-MM-DD), `{slug}` (slug of the typed name, else HHMMSS), `{repo}` (checkout folder name), `{project}` (slug of the name), `{branch}` (folder template only).
- `herdr` functions: `knownAgents`, `window` (the platform, for ⌘ or alt hints), `exec`, `hc`, `run`, `focused`, `spaces`, `home`, `appHome`, `readTextFile`, `writeTextFile`, `pickFolder`, `props`, `theme`, `shared`, `setShared`, `closeOverlay`. `fs/promises` for the log and the demo file.
- Commands: `space.new {name, folder, tab, argv, task}`, `space.select {id}`, `space.close {id}`, `tab.new {space, name, folder, argv}` (through `herdr-app do`), `pane.focus {pane}`, and `herdr-app do pane.split` through `exec`. `hc ls --json`, `hc get <t> --json` and `hc send <t> -- <text>` for typed-after-start prompts (`ls` prints a terminal's agent status as a string, `get` as an object, `"status":{"app":…,"state":"idle"}`, or `null`); `hc run --bg --rm --no-parent --no-notify [--cwd … --label herdr.space=<id> --label herdr.tab=setup-<ts>] -- sh -c <line>` for the setup tab and the prompt helper, and `tab.rename {id, name}` for the "setup" label.
- The chain shape: `export PROJECTS_…=…; cd <folder> && sh -ec "$(printf '%s\n' '<step>' …)" && touch .projects-setup-done`, wrapped by `chainThenAgent` (`… && cd <pane folder> && exec <agent> [prompt] || exec "$SHELL"`) or `chainAlone` (`… || exec "$SHELL"`) in `lib.js`; `setupChain` builds the inner part. The helper is `sh bin/send-prompt.sh <terminal> <prompt-file> <agent-program> [timeout]`: it polls `hc get <terminal> --json` every 2 s and sends the prompt file with `hc send <t> -- <text>` when the agent's status state is idle or done, or when that program has been the pane's foreground for 6 s with no status; it exits 1 when the agent is blocked, the prompt file is empty or `hc get` fails 4 times in a row (the terminal is gone), and 2 after the timeout (1800 s). It removes the prompt file on every exit, and the mod removes it when the helper can't be started. The prompt file is `data/projects/prompt-<ms>.txt`.
- Programs run: `git`, `test`, `touch`, `sleep`, `hc`, `herdr-app` (pane splits), and `sh -c` for the setup chain, inline setup steps, the copy script and command panes.
- Widgets from `gpui-base`: `InputState`, `Input`, `v_virtual_list`, `VirtualListScrollHandle` and `Scrollbar` (a handler can't be registered inside a virtual list's row renderer, so each list has one `on_item_click`; a double-click is two clicks timed by the mod).
- Colors: only theme names (`t.selected`, `t.dim`, …) or hex; a string like `"transparent"` is rejected and the whole view stops rendering.
- Logs: errors always go to `~/.config/herdr-app/data/projects.log`; `projects.debug` next to it turns on key, click and command logging. `projects.demo` (JSON) opens the picker in a given view for screenshots; see CONTRIBUTING.md.
- The shared lock `projects.lock` (shared state, a timestamp; a lock older than 25 s counts as stale) serializes the picker and the watcher so two builds never interleave.
- Two top-level keys of `projects.json` are JSON-only, with no editor, and are kept when the editor saves:
  - `"autoLayouts": [{ "repo": "*", "branch": "release", "layout": "deploy" }]`: `repo` is a repo name or `*` (default `*`), `branch` is optional, `layout` names a pane layout from `layouts` (or a shipped one). Tabs and panes only, no copy or setup.
  - `"defaultAgent": { "agent": "claude", "args": "--model opus" }`: an agent pane in an `autoLayouts` layout that leaves `agent` empty takes this, else it is a plain shell.

## Watch out

- **`render()` must not read live herdr data.** Herdr draws a view again whenever data it read changes (spaces, agents, terminals, focus, shared state), which is constant while an agent works, and a draw that takes a while is cut off when the next one is asked for ("This view could not be re-rendered … interrupted"). The picker copies spaces, space colors, recent projects and the platform into `this.snap` (`takeSnapshot`), refreshes it every 3 s, and asks for a draw only if it changed; a draw reads the copy. Only the theme is read live. With the draw reading live data, the popup was interrupted on every open and lagged for seconds per key press; with the copy it passed 3 of 3 trials with the card off and 2 of 3 with it on.

- Setup commands and tab and pane commands run arbitrary shell from the config file. Tell the person before installing a shared config.
- **The popup cancels its tasks when it closes** (Esc or a click beside it), so nothing in the mod waits for setup. Long steps run in a terminal the app owns (the agent pane or the setup tab), and the prompt helper is started detached for the same reason.
- `exec` stops after 30 seconds. That only limits git and the copy calls, and inline setup (`quickSetup`), where a slow step is cut off, logged as "setup stopped", and the marker is not written.
- A failed setup command stops the remaining ones; the space still opens. With the agent after setup it has no agent and its pane sits at a shell; with the agent beside setup the setup tab stays at a shell. The marker is not written, so the next open runs the setup again.
- If the prompt helper is killed outright (the machine shuts down mid-wait) its `data/projects/prompt-<ms>.txt` stays behind; delete such files by hand. Its own exits (sent, blocked, gone, timeout) remove it.
- The first prompt goes to the agent as a command-line argument (`space.new {task}`) by default, which `hermes` and some other agents reject as an unknown subcommand. The Prompt button switches the project to "typed after start": the agent is started bare and the prompt is sent with `hc send` once `hc ls --json` shows it idle (6 s after start if it never reports a status, never while blocked). Picking the Hermes agent button sets this automatically.
- Each agent pane's command and arguments are split into words, with '…' and "…" keeping spaces together; there's no other shell syntax. The first prompt is only sent when an agent pane exists.
- Herdr nests a worktree space under its repo's space only while a space on the main checkout is open (its sidebar groups by git common dir). With `repoSpace` off and no such space open, worktree spaces sit at the top level. Closing the repo's space later makes its worktrees top-level again.
- A tab's splits start from the tab's first pane, found from `herdr-app ls` right after `space.new` or `tab.new`; the typed-prompt terminal is found before the splits are made, since they also start in the folder.
- `ratio` and `label` are not supported: the app splits evenly and has no pane rename. `terminal.open` cannot target a pane, so every pane is made with `pane.split`.
- The first agent pane gets the prompt, which with the command-line argument mode is added to that pane's command; a later agent pane starts bare.
- Extra tabs are made in the space found from `herdr-app ls` right after `space.new`; the terminal for a typed prompt is found as the new live terminal that starts in the new folder, so two launches into one folder at once could confuse it.
- Local folders only: no `machine` field yet.
- Click handling and `cmd` shortcuts on macOS are untested: Herdr may use some cmd keys itself (e.g. cmd-n), so the buttons are the fallback.
- The setup tab is an `hc run` terminal, not a mod-made tab: if herdr never shows it, the mod logs "setup tab not renamed" and leaves it unnamed.
- Typed-after-start needs `hc` on the PATH; an unknown agent counts as ready once something other than a shell has been in the foreground for 6 s.
- On the launch screen the prompt box eats Enter (it inserts a newline and fires `submit` on every Enter), so launching from it relies on ctrl+Enter reaching the screen's key handler, which it does; Cmd+Enter does not.
- **Launcher off means watcher off:** a hidden block's copy may never start, and only the copy in the chosen slot acts. Keep the button shown somewhere if you rely on auto-layout.
- **One-pane guard:** a space with more than one tab or pane is never touched, so a space you rearranged before the 2 s poll saw it is left alone.
- **The lock is not atomic:** `projects.lock` is a read then a write of shared state, so two builds starting in the same instant could both pass; the 25 s stale rule frees a lock left by a crash.
- **Status-less agents:** an agent that reports no status is told apart from a shell by its foreground command; an unusual wrapper may be seen as a shell and get the agent line typed into it.
- **Typing into a shell races the person:** the watcher types only when `hc read` shows a bare prompt (the last non-empty line ends in `$`, `%`, `>` or `#` with nothing after it), and gives up after 10 s, logged and counted in the toast. A key pressed between that read and `hc send` still lands in front of the line, and a prompt ending in another character is never seen as bare, so its line is always skipped.

## Done when

- `herdr-app check mods/projects` passes; `ctrl-alt-p` / `cmd-alt-p` opens a popup titled Projects.
- A `data/projects.json` copied from a project-presets file opens the same spaces it did there: the agent with its prompt, the layout's panes, the extra tabs.
- The Shop example (four tabs, two folders, a split api tab) opens four tabs named agent, web, api, git with web in `frontend/`, api in `backend/` split right into `backend/db`, and git running lazygit.
- A tab whose folder does not exist is refused with `Tab "web" pane 1: folder does not exist: …` and no space is created.
- The card lists `server ×2` for a split tab and shows the first agent pane's agent.
- The editor adds, removes and reorders tabs and panes, applies a shipped layout's panes to a tab, and Save refuses a nameless tab with `Tab 2 needs a name`.
- Ask mode with `copy: [".env"]`, `worktree.setup: ["sleep 20"]`, a prompt typed and Agent after setup: the new space's agent pane shows the sleep running, `hc ls` shows its foreground change to the agent after 20 s, `.env` is in the worktree, `.projects-setup-done` exists and `git status` there is clean.
- The same with Agent with setup: the agent answers while a "setup" tab runs the sleep, and that tab disappears when it ends.
- Opening the same worktree again lists only the startup setup on the busy screen: no copy, no marker touched.
- An empty prompt starts the agent bare; a branch typed `feat/x` creates `feat/x`.
- A failing setup step (`false`) leaves the agent pane at a shell with the output above it and no agent.
- Auto-layout (needs the launcher block in the layout; the demo file `{ "view": "launcher-setup" }` sets it up without clicks), on a throwaway project with `autoLayout: true`, `copy: [".env"]`, `worktree.setup: ["sleep 5"]`, `startup.setup: ["echo hi"]`, agent claude, timing `with`, tabs agent and a "git" tab running `top`:
  - `herdr-app do space.new '{"folder":"<checkout>"}'` gets the project's tabs within about 5 s (its first tab renamed to the plan's first tab name, "agent"), and a setup tab that ran `echo hi` and vanished.
  - A worktree made with `git worktree add <wt>` and then opened with an agent (`herdr-app do space.new '{"folder":"<wt>","argv":["claude"]}'`) keeps its agent, gains a setup tab (copy, sleep, echo) and the git tab, and has `.env` and the marker.
  - Closing that worktree's space and opening it again runs only `echo hi`: no copy, the marker untouched.
  - Switching spaces back and forth changes nothing.
